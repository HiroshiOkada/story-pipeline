# 詳細仕様レビュー記録

## 1. 結論

`docs/specification.md` の確定方針を、初期実装に必要なコンポーネント境界、データ契約、正常系、異常系、安全制約へ展開した。レビューで検出した詳細仕様内の不整合は修正済みであり、初期実装を開始できる状態と判断する。

本レビューは文書仕様を対象とするため、LLM API を使う統合テストは実施していない。実装時には各契約に対応する単体テストと、重要段階での統合テストを別タスクのチェックリストへ含める。

## 3. 実装時に詳細化する事項の解決

| 上位仕様の項目 | 決定 |
| --- | --- |
| state と run の JSON schema | 必須キー、型、列挙値、整合条件、保存順を定義 |
| Git commit message | `Record request NNNN input` と `Complete request NNNN: <status>` |
| 要求・報告 template | 固定見出しと空節の表現を定義 |
| JSONC library | 外部ライブラリを使わず、内部字句処理と標準 `json` を使用 |
| 管理対象許可リスト | パス全体へ一致する固定リストを定義 |
| 章・話の採番 | 1始まり、単調増加、欠番再利用禁止、上限9999 |

## 4. 異常系レビュー

| 分類 | 期待動作 | 仕様箇所 |
| --- | --- | --- |
| 未初期化・空でないディレクトリ | 副作用なく停止 | `README.md`, `cli.md` |
| 設定不正・未知キー・重複キー | 場所を示して停止 | `files-and-templates.md` |
| 状態と実ファイルの不一致 | 自動修復せず検出 | `state-and-runs.md`, `cli.md` |
| process 中断 | 確定済み hash だけを採用し再開 | `state-and-runs.md` |
| staged/競合/履歴操作中 | 利用者の状態を変えず停止 | `git-safety.md` |
| 管理ファイルの直接編集 | tracked の明示パスだけ復元 | `git-safety.md` |
| stale lock | 自動削除せず確認を要求 | `git-safety.md` |
| API 認証・一時障害・拒否 | 分類別に停止・再試行・確認待ち | `llm.md` |
| JSON 応答不正 | 上限内で再生成し、推測抽出しない | `llm.md` |
| context 長超過 | 章要約以外で黙って圧縮しない | `llm.md` |
| 修正引用が非一意 | 変更せず確認待ち | `pipeline.md` |
| 1,000行以上の変更 | 適用前に停止し、後続要求単位で分割 | `git-safety.md` |

## 5. 安全要件レビュー

- 作品ルート外へ到達する相対パスとシンボリックリンクを拒否する。
- API 接続確認に成功するまで作品ファイルを変更しない。
- API キー、認証 header、応答全文をログ、状態、報告へ保存しない。
- stage 済み変更、想定外ファイル、追加資料を暗黙に取り込まない。
- repository 全体の restore、reset、clean、履歴書き換え、remote 操作を禁止する。
- 根本方針、非一意な修正対象、未完成判定を LLM の推測で確定しない。
- LLM 呼び出し上限を永続化し、process 再起動で回避できないようにする。

## 6. レビューで修正した事項

1. 上位仕様では終了 status にかかわらず次要求を作成するため、`cli.md` の failed 時に作成しない記述を修正した。
2. `awaiting_human` は終了済み要求であり、人間の回答は次要求になるため、旧 run を再開する状態遷移を後続要求の新規実行へ修正した。
3. JSON5 全機能を暗黙許可しないよう、JSONC の受理構文と実装方式を確定した。
4. 追加仕様に基づき、モデルの `max_tokens` は省略可能、実効既定値は 128K を表す `131072` とした。明示値を優先し、設定ファイル自体は書き換えないことを確認した。

## 8. 実装タスクへの引き継ぎ

実装計画では少なくとも次を独立したチェック項目とする。

1. 設定、状態、ファイルモデルと schema 検証
2. `init`, `status`, `validate` の副作用なし動作
3. Git 分類、明示 path commit、復元、lock
4. OpenAI 互換 client、秘密除去、再試行、fallback
5. 要求解釈と各制作 phase
6. 中断再開、異常系、1,000行制限
7. unit test と API を使わない統合 test
8. 指定された OpenRouter 構成による重要段階の統合 test
