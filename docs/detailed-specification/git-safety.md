# Git と作業ツリーの安全仕様

## 1. 前提

`run` は作品ルートが Git ワークツリー内にあり、作品ルートと Git ワークツリーのルートが一致する場合だけ実行できる。親リポジトリの一部として置かれた作品、submodule、bare repository、マージ・rebase・cherry-pick・revert・bisect 中のリポジトリでは変更せず停止する。

detached HEAD はコミット後の参照先を失う可能性があるため停止する。Git hooks と署名設定は利用者の設定を尊重し、迂回しない。コミット失敗時は本処理を開始しない、または終了状態を追加変更せず停止する。

## 2. パス分類

作業ツリーの tracked、untracked、ignored の全変更を porcelain v2 の NUL 区切り形式で取得し、正規化後の作品ルート相対パスを次の排他的分類へ割り当てる。

### 2.1 人間入力

- 処理対象の `requests/NNNN.md`
- `story-pipeline-config.jsonc`
- 処理対象要求でコミットを明示された追加資料

要求と設定は開始時コミットの対象とする。追加資料は要求本文から構造化された相対パスとして一意に抽出できる場合だけ対象とする。

### 2.2 CLI 管理ファイル

厳密な許可リストは次のとおりとする。

```text
concept.md
world.md
characters.md
plot.md
style.md
canon.md
chapters/[0-9][0-9][0-9][0-9].md
episode_plans/[0-9][0-9][0-9][0-9].md
episodes/[0-9][0-9][0-9][0-9].md
requests/[0-9][0-9][0-9][0-9]_agent.md
.story-pipeline/state.json
.story-pipeline/runs/[0-9][0-9][0-9][0-9].json
```

許可リストはパス全体へ一致させる。類似名、サブディレクトリ、5桁番号、バックアップ拡張子を含めない。`requests/NNNN.md`、設定、追加資料は管理ファイルではない。

### 2.3 一時・除外ファイル

- `.story-pipeline/run.lock`
- 作品ルート内の `.env`
- CLI が同一実行中に作成した一時ファイル

これらはコミットしない。一時ファイル以外が Git 追跡済みなら秘密漏えいの可能性として停止する。

### 2.4 想定外ファイル

上記のいずれにも該当しない全パスとする。内容を変更、削除、stage、commit しない。存在だけでは `run` を妨げないが、処理が同じパスを作成する必要が生じた場合は停止する。

## 3. 開始時検査と復元

### 3.1 index の保護

CLI 開始前から staged されている変更が 1 件でもあれば、対象分類を問わず停止する。利用者の stage 状態を変更したり、一緒にコミットしたりしない。

競合状態、intent-to-add、skip-worktree、assume-unchanged が管理対象または人間入力に設定されている場合も停止する。rename と copy は元・先両方を分類する。

### 3.2 管理ファイルの復元

- tracked 管理ファイルの変更・削除は、パスを明示した `git restore --worktree --source=HEAD -- <path...>` 相当で復元する。
- untracked 管理ファイルは、それが今回の実行で作成されたと証明できないため削除しない。競合として停止する。
- ディレクトリ全体、`.`、glob、pathspec magic を復元対象へ渡さない。
- 復元前に対象一覧を確定し、標準出力へ表示する。
- 復元後に状態を再取得し、対象以外の変更が変化していないことを確認する。
- 復元一覧を実行記録と報告へ記載する。

設定や要求の変更は復元してはならない。想定外ファイルの変更も復元しない。

## 4. 追加資料

要求は「追加資料として次のファイルを開始時コミットに含める」のような明示と、コード表記された相対パスを含まなければならない。

指定パスについて次を検査する。

1. 作品ルート配下の通常ファイルである。
2. シンボリックリンクでない。
3. `.git`、`.story-pipeline`、`.env`、設定済み dotenv、管理ファイル、人間入力と重ならない。
4. 秘密の可能性が高い名前または内容を持たない。
5. ディレクトリ指定、glob、絶対パスでない。

秘密の可能性の検査では少なくとも秘密鍵ヘッダー、一般的な API key/token/secret/password 代入、dotenv 形式を検出する。検出時は内容を表示せず、人間の確認待ちとしてコミットしない。指定外ファイルを同じディレクトリから追加しない。

## 5. コミット

### 5.1 staging

コミットごとに対象パスを明示して stage する。`git add .`、`git add -A`、ディレクトリ単位の add を使用しない。stage 後に index のパス一覧を取得し、予定集合と完全一致しなければ commit せず停止する。

### 5.2 開始時コミット

対象は、変更のある処理要求、設定、許可済み追加資料だけとする。変更がなければ空コミットを作らない。形式は次とする。

```text
Record request NNNN input
```

本文が必要な場合は `Additional material: path` をパスごとに記す。要求番号は4桁で表示する。

### 5.3 終了時コミット

対象は今回の実行で作成・変更した管理ファイルだけとする。開始前から存在した想定外変更を含めない。形式は次とする。

```text
Complete request NNNN: <status>
```

`status` は `completed`、`failed`、`awaiting-human` のいずれかとする。コミット本文に phase と主な成果物パスを記載できる。記録対象がなければ空コミットを作らない。

終了時コミット成功後に次要求ファイルを作成し、stage しない。`git status` でそのファイルだけが新規未追跡であることを確認する。ただし開始時からの想定外変更はそのまま残っていてよい。

## 6. 禁止操作

- `git reset`（すべての形式）
- `git clean`
- repository 全体またはディレクトリを対象とする restore/checkout
- commit amend、rebase、force push、履歴書き換え
- hook や署名検証の無効化
- branch の作成、切り替え、merge、push
- 利用者設定の変更

CLI はローカルコミットまでを責務とし、リモート操作を行わない。

## 7. ロック

### 7.1 形式

`.story-pipeline/run.lock` は排他的作成し、次を JSON で保存する。

```json
{
  "schema_version": 1,
  "pid": 12345,
  "hostname": "example-host",
  "started_at": "2026-07-22T01:23:45Z",
  "request_number": 3
}
```

要求決定前に取得する場合、`request_number` は `null` とし、決定後に原子的に更新する。

### 7.2 競合と stale 判定

ロックが存在する場合、同一 hostname で PID が生存していれば `6` で停止する。別 hostname、PID の確認権限がない場合、壊れた JSON、起動時刻が未来の場合は安全に stale と判断できないため停止し、パスと確認方法を案内する。

同一 hostname で PID が存在せず、対応する running 実行記録がある場合だけ stale lock と判定できる。それでも自動削除は行わず、ロック内容と実行記録を `validate` で提示する。初期実装では利用者がプロセス不存在を確認してロックを削除する。

## 8. 1,000 行制限

差分は本処理開始前の HEAD と採用予定の管理ファイル内容を比較する。追加行と、置換で新しくなる行を数え、純粋な削除行は数えない。Git の通常 diff で `+` の行（ヘッダーを除く）を合計する実装でよい。

- 合計 `0..999` 行は処理できる。
- 合計 `1000` 行以上と判明した時点で、管理ファイルへ変更を適用しない。
- 見積もり、対象、分割単位を報告し、`awaiting_human` とする。
- 次要求の明示的な「続けてください」ごとに最大 1,000 行までを許可する。
- 許可済み回でも 1,000 行を超えて適用してはならず、決定的な章・話・セクション境界で分割する。

タスク状態、実行記録、報告自体は作品内容ではないため行数計算から除外するが、安全のため不必要に肥大化させない。
