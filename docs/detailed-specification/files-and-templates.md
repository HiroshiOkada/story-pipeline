# ファイル、設定、テンプレート仕様

## 1. scaffold

`init` は対象ディレクトリに次を作成する。

```text
story-pipeline-config.jsonc
requests/0000.md
chapters/
episode_plans/
episodes/
.story-pipeline/state.json
.gitignore
```

ディレクトリとファイルの作成に途中で失敗した場合、今回作成したパスだけを削除して開始前の状態へ戻す。既存パスは削除・変更しない。Git リポジトリでなければ、全ファイルの作成成功後に `git init` を実行する。初期コミットは作成しない。

`.gitignore` が新規作成される場合の内容は次のとおりとする。

```gitignore
.env
.story-pipeline/run.lock
```

## 2. 設定ファイル

### 2.1 JSONC の解釈

- UTF-8 の JSON に、行コメント `//` とブロックコメント `/* ... */` および末尾カンマを許可する。
- 文字列内のコメント記号は文字として扱う。
- 重複キーはエラーとする。
- 未知のキーは、そのキーの JSON Pointer を示してエラーとする。
- `~` は `dotenv.files` の各パスでだけ展開する。
- 相対パスは作品ルートを基準に解決する。

### 2.2 トップレベル

| キー | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `config_version` | integer | 必須 | `1` |
| `dotenv` | object | 必須 | `files` を持つ |
| `providers` | object | 必須 | 1 件以上 |
| `models` | object | 必須 | 1 件以上 |
| `roles` | object | 必須 | 下記の必須 role を持つ |
| `limits` | object | 必須 | すべて正の整数 |
| `request` | object | 必須 | タイムアウトと再試行を持つ |

必須 role は `planner`、`writer`、`reviewer`、`reviser`、`summarizer` とする。同じモデル定義を複数 role で参照してよい。

### 2.3 接続定義

`providers.<name>` は次を持つ。

| キー | 型 | 制約 |
| --- | --- | --- |
| `base_url` | string | `http` または `https` の絶対 URL。末尾 `/` は内部で除去 |
| `api_key_env` | string | 環境変数名 `[A-Za-z_][A-Za-z0-9_]*` |

`models.<name>` は次を持つ。

| キー | 型 | 制約 |
| --- | --- | --- |
| `provider` | string | 存在する provider 名 |
| `model` | string | 空でない API 上のモデル識別子 |
| `max_tokens` | integer | 1 以上 |
| `parameters` | object | 任意。温度など Chat Completions API の追加パラメーター |

`parameters` に `model`、`messages`、`max_tokens`、認証情報、URL を指定してはならない。role の値はモデル名の非空配列で、全参照先が存在し、重複しないものとする。

### 2.4 制限値

| キー | 意味 | scaffold 既定値 |
| --- | --- | --- |
| `generation_calls` | 1 要求内の生成呼び出し上限 | `3` |
| `review_calls` | 1 要求内の評価呼び出し上限 | `3` |
| `revision_calls` | 1 要求内の改稿呼び出し上限 | `3` |
| `summary_calls` | 1 要求内の要約呼び出し上限 | `3` |
| `retry_calls_per_request` | 1 論理呼び出し内の再送回数上限 | `2` |
| `max_changed_lines` | 確認なしで変更できる管理ファイルの行数 | `999` |

`request.timeout_seconds` の既定値は `120`、`request.retry_attempts` の既定値は `3` とする。通信試行総数は初回 1 回に `retry_attempts` を加えた数ではなく、`retry_attempts` 自体とする。`retry_calls_per_request` と値が異なる場合は、より小さい方を通信再試行上限として使用する。

### 2.5 `.env`

`dotenv.files` は記載順に読む。存在しないファイルは警告とし、読めないファイルは設定エラーとする。プロセス開始時に存在する環境変数を保持し、先に読んだ `.env` の値も後のファイルで上書きしない。必要な provider を初めて使う直前に、対応する環境変数が空でないことを検証する。

## 3. Markdown テンプレート

見出しが不要な場合も削除せず、「なし」と記載する。これにより報告の機械的な検査を可能にする。

### 3.1 初期要求 `requests/0000.md`

```markdown
# 作品作成要求

## 作りたい作品

<!-- ジャンル、着想、読者、長さなどを記述してください。 -->

## 必須条件

<!-- 必ず守る内容を記述してください。 -->

## 禁止事項

<!-- 含めてほしくない内容を記述してください。 -->
```

後続要求は次の最小テンプレートで作る。

```markdown
# 追加要求

<!-- 継続、修正、追加、再検討などの要求を記述してください。 -->
```

コメントだけ、または空白だけの要求は未処理要求として検出するが、`run` では内容不足として副作用なく停止する。

### 3.2 処理報告 `requests/NNNN_agent.md`

```markdown
# 要求 NNNN 処理報告

## 受け付けた要求
## 要求の解釈
## 実行した処理
## 作成・変更したファイル
## 評価と改稿
## 物語・設定上の変更
## 未解決の問題
## 人間に判断してほしい事項
## 次回の標準処理
```

報告には要求本文を全文複製せず、要点を記す。「作成・変更したファイル」には作品ルート相対パスを列挙する。失敗時はエラー分類、失敗工程、再開可能性を「未解決の問題」に含める。

### 3.3 作品ファイル

作品ファイルは固定見出しを持つが、要求に応じて下位見出しを追加できる。

| ファイル | 必須の最上位セクション |
| --- | --- |
| `concept.md` | タイトル、ジャンル、想定読者、中心的な着想、テーマ、規模、連載方針、必須条件、禁止事項、仮定 |
| `world.md` | 舞台、社会・制度、固有ルール、場所、時系列上の前提、未確定事項 |
| `characters.md` | 人物一覧、関係、人物別の目的・変化・口調・状態 |
| `plot.md` | 開始状況、転換点、クライマックス、結末、人物変化、伏線、章構成 |
| `style.md` | 視点、時制、文体、表記、段落・改行、会話、固有の禁止表現 |
| `canon.md` | 確定事実、人物状態、時系列、伏線、用語・表記 |
| `chapters/NNNN.md` | 目的、開始状態、終了状態、主要な出来事、収録話、接続条件、完成後のあらすじ |
| `episode_plans/NNNN.md` | 目的、登場人物、開始状態、終了状態、場面、開示情報、感情変化、伏線、次話への引き、目標文字数 |
| `episodes/NNNN.md` | 話タイトル、本文 |

## 4. 採番規則

### 4.1 要求番号

- 初期要求は `0000` とする。
- 次の要求番号は、正規表現 `^[0-9]{4}(?:_agent)?\.md$` に一致する `requests` 直下の全ファイルから最大番号を求め、その値に 1 を加える。
- 同じ番号の要求と報告は 1 組として扱う。
- 4 桁で表せる最大値 `9999` の次は自動作成せず、番号枯渇として停止する。
- 番号の欠番は再利用しない。
- 要求ファイルが複数未処理なら整数値が最小の 1 件だけを対象にする。

### 4.2 章番号と話番号

- 章と話はそれぞれ `0001` から開始する。
- 番号は作品内で単調増加し、削除後も再利用しない。
- `chapters/NNNN.md` の「収録話」には話番号を明記する。話番号自体は章ごとにリセットしない。
- 次番号は該当ディレクトリの正規ファイル名と、状態に記録された最新番号の大きい方に 1 を加える。
- 既存ファイルと状態が矛盾する場合は自動採番せず、`validate` エラーとする。
- `9999` を超える場合は人間の判断待ちとして停止する。
