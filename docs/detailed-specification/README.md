# Story Pipeline 詳細仕様

## 1. 位置づけ

本ディレクトリの文書は、`docs/specification.md` を初期実装へ落とし込むための詳細仕様である。両者が矛盾する場合は `docs/specification.md` を優先し、詳細仕様を修正する。

## 2. 文書構成

| 文書 | 内容 |
| --- | --- |
| `README.md` | 文書体系、用語、共通規約、作品ルート判定 |
| `files-and-templates.md` | scaffold、設定、テンプレート、採番 |
| `state-and-runs.md` | 永続状態、要求別実行記録、状態遷移、再開 |
| `cli.md` | コマンド、引数、出力、終了コード、副作用 |
| `git-safety.md` | 作業ツリー分類、許可リスト、コミット、復元、ロック |
| `llm.md` | API 呼び出し、応答検証、再試行、フォールバック、上限 |
| `pipeline.md` | 要求解釈、制作フェーズ、評価、改稿、報告 |
| `verification.md` | 仕様整合性、異常系、安全性、実装可能性の確認結果 |

## 3. 規範表現

- 「必須」「しなければならない」は実装上の必須要件を表す。
- 「禁止」「してはならない」は実装上許容しない動作を表す。
- 「推奨」「する」は、特記がない限り既定の動作を表す。
- 「可能」「できる」は任意機能または条件付き動作を表す。
- パスは、絶対パスと明記しない限り作品ルートからの相対パスで表す。
- `NNNN` は 0 埋めした 4 桁の 10 進整数を表す。

## 4. 用語

| 用語 | 定義 |
| --- | --- |
| 作品ルート | 対象作品の `story-pipeline-config.jsonc` が置かれたディレクトリ |
| 要求 | 人間が作成する `requests/NNNN.md` |
| 報告 | CLI が要求処理の結果を記す `requests/NNNN_agent.md` |
| 管理ファイル | CLI が内容を生成・更新し、開始時に直接編集を検出・復元するファイル |
| 人間入力 | 人間による編集を許可し、開始時コミットの候補にする要求、設定、明示された追加資料 |
| 実行 | 1 件の要求を受理してから報告と状態を終了時コミットへ保存するまでの処理 |
| 工程 | 実行内で再開可能な最小処理単位 |
| 創作呼び出し | 生成、評価、改稿、要約など、作品内容を扱う LLM 呼び出し |
| 通信再試行 | 同一の論理的な創作呼び出しを、一時的 API 障害のため再送すること |
| 最良版 | 評価済み候補のうち、必須条件と整合性を満たした上で採用スコアが最高の版 |

## 5. 共通規約

### 5.1 文字コードと改行

- テキストファイルは UTF-8（BOM なし）で読み書きする。
- CLI が新規作成するテキストファイルの改行は LF とする。
- Markdown の見出し、JSON のキー、列挙値は本詳細仕様で定義した表記を使用する。
- JSON の日時は UTC の RFC 3339 形式（例: `2026-07-22T01:23:45Z`）とする。

### 5.2 パスの安全性

- CLI が受け取った相対パスは正規化後に作品ルート配下であることを確認する。
- シンボリックリンクを解決した実体が作品ルート外になるパスは読み取り専用の参照も含め、要求処理対象にしない。
- ファイル操作は可能な限り一時ファイルへ書き、同一ファイルシステム上の置換で確定する。
- ファイル名の番号比較は文字列順ではなく整数値で行う。

### 5.3 決定の優先順位

処理判断は、上から順に優先する。

1. 処理対象となる最新の人間要求
2. 過去の人間要求に明記された未変更の条件
3. 採用済みの作品ファイルと確定事実
4. 設定ファイル
5. CLI の既定値と LLM の仮定

同じ優先順位に解消不能な矛盾がある場合は `awaiting_human` とし、推測で一方を採用しない。

### 5.4 決定的処理と LLM 処理

採番、ファイル検出、スキーマ検証、ハッシュ計算、差分行数、Git 状態、呼び出し回数、状態遷移はプログラムで決定する。LLM にこれらの最終判断を委ねてはならない。要求の意味、物語内容、品質評価など自然言語上の判断だけを LLM に委ねる。

## 6. 作品ルート判定

### 6.1 `init` 以外

1. 起動時のカレントディレクトリを実体パスへ解決する。
2. カレントディレクトリから親へ順に `story-pipeline-config.jsonc` を検索する。
3. 最初に見つかったファイルの親ディレクトリを作品ルートとする。
4. ファイルシステムのルートまで見つからなければ、未初期化として副作用なく終了する。

探索中に見つけた設定ファイルが通常ファイルでない、読めない、または解決後に探索対象ディレクトリ外を指す場合は、その場で設定エラーとする。さらに親へ探索を続けて別作品を暗黙選択してはならない。

### 6.2 `init`

- 明示的な対象パスがなければカレントディレクトリを対象とする。
- 対象パスは存在するディレクトリでなければならない。
- 対象に `story-pipeline-config.jsonc` があれば初期化済みと判定し、上書きしない。
- 対象が空、または `.git` だけを含む場合に scaffold を作成できる。
- それ以外の空でない未初期化ディレクトリでは、変更せずに終了する。
- 既存 Git repository の差分を変更せず、scaffold の既知4ファイルだけを `Initialize story project` commit に保存する。
- Git identity 不足や commit 失敗時は scaffold を保持し、今回の stage を外して復旧方法を案内する。
- 親ディレクトリに別作品の設定があっても、`init` の対象判定には使用しない。

## 7. 互換性

- 状態および実行記録は `schema_version` で形式を識別する。
- 初期実装の形式は `1` とする。
- 未対応の新しいバージョンは変更せずエラーにする。
- 古いバージョンの移行処理は、対応する移行仕様が追加されるまで実施しない。
