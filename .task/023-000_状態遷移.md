# フェーズ023: 状態遷移

## ゴール

全章の `## 収録話` から検証済みの章・話対応表を構築し、本文採用後と章改稿後の次状態を一箇所で決定する。章内最終話から章改稿、次章、全体改稿、完成へ確実に到達し、状態と成果物の矛盾を具体的に診断し、既存の誤った状態を明示操作で安全に移行できるようにする。

## 対象

- I-07: 最終話採用後も常に次話計画へ進み、章改稿・全体改稿へ到達しない問題。
- 全 `chapters/NNNN.md` の章・話対応表と、重複・欠落・逆順・非連続の検査。
- 本文採用後と章改稿完了後の状態遷移関数。
- phase、current/next chapter、next episode、completed 集合の横断検証。
- 既存状態を作品ファイルと Git の安全条件に基づいて修正する明示 migration。
- 話・章番号 9999 の飽和境界と人間判断停止。

## 完了条件

- 1章1話、1章複数話、複数章の各構成で、本文から章改稿、次章または全体改稿、完成まで到達できる。
- 収録話の重複、欠落、逆順、非連続を具体的な章ファイル location 付きで拒否する。
- phase と current/next/completed の矛盾、完了話を飛ばす `next_episode`、全章完了後の誤った phase を `validate` が拒否する。
- 既存3作品相当の状態を明示 migration で `chapter_revision` と正しい sentinel へ移し、本文と既存 Git 履歴を変更しない。
- 9999 を最終話・最終章に含む構成で番号を循環・再利用せず、追加対象が必要なら人間判断へ安全停止する。
- API 非依存の回帰テストと全既存テストが成功する。
