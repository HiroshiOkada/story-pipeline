# 全体改稿と完成判定の作業目標

## ゴール

詳細仕様の `final_revision` フェーズを実装し、完成済み各章の評価を統合して、作品全体の因果、人物変化、伏線、結末、要求適合を評価し、必要な局所改稿と再評価を経て、小説全体を明示的に完成判定できるようにする。

## 完了条件

- 全本文を扱える場合は本文を、扱えない場合は章あらすじと隣接章接続情報を使う全体評価コンテキストを構築できる。
- 全体の因果、人物変化、伏線、結末、要求適合、設定・時系列・視点の整合性を構造化評価できる。
- 問題箇所へ限定した改稿候補について、対象範囲外が不変であることを決定的に検査できる。
- 大規模な再構成や根本方針変更は自動採用せず、人間判断事項として返せる。
- 改稿後の再評価を行い、明示的な `complete=true` の場合だけ `completed` 状態への更新候補を返せる。
- 単体テスト、API を使わない統合テスト、指定 OpenRouter 構成での全体改稿試験が成功する。

## 対象外

- `run` コマンド全体のオーケストレーション
- 作品ファイル、state/run JSON の書込み、Git コミット、報告、次要求の作成
- 完成後の新規続編制作
