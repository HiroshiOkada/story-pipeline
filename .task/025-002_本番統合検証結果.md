## 本番検証で修正した不具合

- provider が返す実費を run、report、集計へ欠落と0を区別して記録した。
- 構造化本文から決定的に Markdown を構築し、見出し翻訳と正規表現による出力肥大を防いだ。
- knowledge と章あらすじの根拠を採用本文へ一意に結び付けた。章あらすじは本文由来の列挙候補から選択させ、転記揺れを構造的に防いだ。
- 再開時の検証対象を最新の採用出力 hash に限定した。
- `chapter_revision` と `final_revision` を未作成の次話・次章より優先した。
- 採用候補に未変更文書が含まれても、実差分のある出力だけをGitコミット対象にした。
- 失敗時の安全な評価結果、終了理由、保持用worktreeを診断可能にした。

## リリース判断の根拠

- 3作品すべてで状態遷移、run/report、checkpoint、hash、Git commit、usage/cost が整合した。
- 完了後の3 repository で `validate` が成功した。
- 呼び出し数、費用、時間、writer再生成の停止条件をすべて満たした。
- APIキーその他の秘密値を結果JSON、Markdown、run、reportへ保存していない。

機能回帰テスト、コンパイル、配布物検査、秘密値検査を最終コミットに対して再実行し、成功後に `main` へ統合する。
