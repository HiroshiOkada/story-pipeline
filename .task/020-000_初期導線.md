# フェーズ020: 初期導線

## ゴール

`story-pipeline init` が作成した scaffold を検証済みの初期 commit として保存し、初回要求を記入した利用者が手動の Git 操作なしで `run` を開始できるようにする。同時に、標準的な作成・継続・回答要求で planner が推測した `targets` を作業範囲に使用せず空へ正規化し、明示対象が必要な変更系要求の厳格な検査は維持する。

## 対象

- I-01: `init` が未 commit の管理ファイルを正常結果とし、直後の `run` が安全停止する契約不整合。
- I-02: 標準要求で実際の範囲決定に使わない planner の推測 `targets` を、要求本文との完全一致検査で拒否する契約不整合。

## 完了条件

- 空ディレクトリと既存の空 Git repository の両方で、`init` 後に HEAD が存在し、作業ツリーが clean になる。
- 初期 commit の対象が scaffold の既知ファイル4件に完全一致し、既存差分や利用者ファイルを stage しない。
- Git identity 不足または commit 失敗時に終了コード5で停止し、作成済み scaffold を削除せず、設定方法と手動 commit の選択肢を案内する。
- `create`、`continue`、`answer` と対象を伴わない `mixed` の `targets` を空へ正規化し、状態と成果物から標準範囲を決定する。
- `modify`、`add`、`reconsider` と対象を伴う `mixed` は、要求本文に明示された安全な作品ルート相対パスを必須とする。
- fake client を使う初回 `run` が Git error と target error なしに構想を採用する。
- API 非依存の回帰テストと全既存テストが成功する。
