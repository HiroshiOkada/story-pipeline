# フェーズ022: 本文成果保全

## ゴール

本文生成・評価と knowledge 抽出を独立した再開可能工程へ分け、採用可能な本文を hash で入力へ束縛した内部 checkpoint に保存する。knowledge の一時的失敗では本文を再生成せず、検証済み knowledge と本文、canon、人物状態を一つの正式採用単位として保存し、部分適用や改変を安全に検出できるようにする。

## 対象

- I-04: 本文と knowledge の複合工程が検証失敗の境界と理由を失う問題。
- I-05: knowledge 失敗時に採用可能な本文が失われ、成功時も knowledge 更新が適用されない問題。
- `.story-pipeline/checkpoints/NNNN/draft.json` の検証、保存、再利用、採用状態。
- 本文 JSON、Markdown 機械検査、評価、knowledge の工程分割と validation code。
- evidence の空白・改行正規化と元本文への一意な逆引き。
- 本文、canon、人物状態、state、run の同一採用単位と部分適用検出。

## 完了条件

- 本文評価通過後に knowledge を意図的に失敗させても checkpoint が保存され、再開時の writer と本文 reviewer 呼出しが0になる。
- checkpoint の要求 revision、全入力 hash、本文 hash、評価対象 hash の不一致を検出し、正式成果物として再利用しない。
- knowledge 成功時に本文、canon、人物状態の更新を保存し、出力 hash と checkpoint の `adopted` 状態が一致する。
- 適用途中の出力集合を部分適用として検出し、自動的な続行や上書きをしない。
- 本文外または複数箇所に一致する evidence を拒否し、空白・改行だけが異なる一意 evidence を元本文の完全一致文字列へ解決する。
- 応答本文や秘密を保存せず、検証境界、code、試行番号、候補 hash、サニタイズ済み理由を記録する。
- API 非依存の回帰テストと全既存テストが成功する。
