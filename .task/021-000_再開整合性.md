# フェーズ021: 再開整合性

## ゴール

失敗した run の再開時に、要求が不変か改訂されたか、その改訂が未コミットか commit 済みかを区別し、初回実行境界を保持したまま最新版の要求、入力 commit、適用開始工程を監査可能に記録する。具体的な後続要求を active run が暗黙に無視せず、既存 schema version 1 の実行記録もデータを失わず読み込めるようにする。

## 対象

- I-03: failed run の要求改訂が実行記録と不整合になる問題。
- run schema version 2 の `request_revisions` と `resume_count`。
- unchanged resume、未コミット要求改訂、commit 済み要求改訂の開始処理。
- 自動作成された後続要求と active run の衝突検査。
- schema version 1 の読取 migration と検証。

## 完了条件

- `request_sha256` が常に現在受け入れている要求と一致し、初回 `start_commit` と `started_at` は再開後も不変である。
- 初回および各改訂の hash、入力 commit、受入時刻、適用開始 step を `request_revisions` から復元できる。
- `resume_count` がプロセス再開ごとに増加し、累積 call count と model attempt を保持する。
- 要求改訂時は要求解釈と作業範囲、および入力 hash が変わった依存工程だけを再実行対象に戻す。
- 具体的内容を持つ後続要求が存在するとき、active run の再開として暗黙に無視せず安全停止する。
- schema version 1 の実行記録を version 2 として補完して読み、永続化後に `validate` が成功する。
- API 非依存の回帰テストと全既存テストが成功する。
