# 本文制作フェーズの作業目標

## ゴール

詳細仕様の `drafting` フェーズを実装し、現在要求、採用済み設定、対象話計画、前後関係に基づく次の1話の本文を、機械検査・構造化評価・必要な改稿・整合性再評価を経て採用可能な候補として返し、採用本文で確定した事実だけを canon と人物状態の更新候補へ反映できるようにする。

## 完了条件

- `episodes/NNNN.md` の候補と生成コンテキストに、対象話計画、設定、canon、style、直前話、存在する次話計画が明示的に対応する。
- 固定見出し、対象パス、説明文・JSON混入、実文字数と目標文字数の許容範囲を決定的に検査できる。
- 必須条件、整合性、開始・終了成立、指定文体、読みやすさを構造化評価できる。
- 不採用候補を呼び出し上限内で改稿・再評価し、採用可能な最良候補を選べる。
- 採用本文で提示された事実だけを、出典・成立時点・関係人物付きの canon・人物状態更新候補として検証できる。
- 人間判断が必要な評価と、上限内で解決できない不採用状態を明示的な結果として返せる。
- 単体テスト、API を使わない統合テスト、指定 OpenRouter 構成での本文制作試験が成功する。

## 対象外

- 章・全体改稿と完成判定
- `run` コマンド全体のオーケストレーション
- 作品ファイル、state/run JSON の書込み、Git コミット、報告、次要求の作成
- 採用済み本文に対する部分修正要求
