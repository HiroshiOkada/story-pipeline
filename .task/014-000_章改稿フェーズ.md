# 章改稿フェーズの作業目標

## ゴール

詳細仕様の `chapter_revision` フェーズを実装し、章内の完成話と前後章の接続情報を評価して、局所的な改稿候補、章の完成判定、採用可能な章あらすじを安全に決定できるようにする。

## 完了条件

- 章計画、章内本文、設定、canon、前後章の接続情報から評価コンテキストを構築できる。
- テンポ、反復、出番、時系列、視点、伏線、人物変化、長さを構造化評価できる。
- 問題箇所へ限定した改稿案について、対象範囲外が不変であることを決定的に検査できる。
- 大規模な再構成は自動採用せず、人間判断事項として返せる。
- 改稿後の再評価と章の `complete` 判定を行い、完成時だけ章あらすじと状態更新候補を返せる。
- 単体テスト、API を使わない統合テスト、指定 OpenRouter 構成での章改稿試験が成功する。

## 対象外

- 小説全体の改稿と最終完成判定
- `run` コマンド全体のオーケストレーション
- 作品ファイル、state/run JSON の書込み、Git コミット、報告、次要求の作成
