# フェーズ010: 基礎設定制作フェーズ

## ゴール

採用済みの構想と構造化済みの要求から `world.md`、`characters.md`、`style.md`、`canon.md` を一つの整合単位として生成し、機械検査、構造化評価、必要な改稿を経て、安全に採用できる基礎設定一式を決定する制作フェーズを実装する。

## 完了条件

- 採用済み構想、要求、必須条件、禁止事項を基礎設定用の境界が明瞭な生成コンテキストへ構成できる。
- 4 成果物の必須見出し、空内容、テンプレートコメント、不要な fence を決定的に検査できる。
- `canon.md` が初期時点の確定事実だけを扱い、将来案を確定事項として混入させないよう検査できる。
- reviewer の構造化評価を厳格に検証し、構想不適合または成果物間の整合性 error がある候補を採用しない。
- 呼び出し上限内で生成、評価、改稿を行い、4 成果物を同一候補から不可分に採用できる。
- 人間判断が必要な評価と、上限内で解決できない不採用状態を明示的な結果として返せる。
- 単体テスト、API を使わない統合テスト、指定 OpenRouter 構成での基礎設定制作試験が成功する。

## 対象外

- 全体構成、話計画、本文、章・全体改稿の制作
- `run` コマンド全体のオーケストレーション
- state/run JSON の書込み、Git コミット、報告、次要求の作成
- 採用済み基礎設定に対する部分修正要求
