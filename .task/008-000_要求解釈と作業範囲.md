# フェーズ008: 要求解釈と作業範囲

## ゴール

`run` が処理すべき要求を決定し、人間の記述を厳格な構造へ解釈したうえで、現在状態から今回実行する制作単位を決定できる基盤を実装する。

## 完了条件

- 再開対象と最若番号の未処理要求を混同せず、安全な通常ファイルだけを選択できる。
- 空白・テンプレートコメントだけの要求を作品変更前に拒否できる。
- 要求解釈 JSON のキー、型、列挙値、番号、相対パスを厳格に検証できる。
- pending decision がある場合、後続要求の回答 ID を過不足なく照合できる。
- 標準継続規則から次の自然な制作単位と更新候補を決定できる。
- LLM に渡す要求と作品コンテキストを、相対パス・SHA-256・明瞭な境界付きで構築できる。
- 単体テスト、API を使わない統合テスト、指定 OpenRouter 構成での解釈試験が成功する。

## 対象外

- 各制作フェーズの成果物生成、評価、改稿、採用
- run/state の書込みと呼び出し回数の永続化
- Git 開始時・終了時処理のオーケストレーション
- 追加資料の秘密検査と開始時コミット
